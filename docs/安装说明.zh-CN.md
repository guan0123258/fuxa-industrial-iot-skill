# 安装说明（Codex / 本地脚本）

## Codex 项目级安装（推荐先这样测试）

把整个 `fuxa-industrial-iot-skill` 文件夹复制到项目：

```text
你的项目/
└── .agents/
    └── skills/
        └── fuxa-industrial-iot-skill/
            ├── SKILL.md
            ├── agents/openai.yaml
            ├── scripts/
            ├── references/
            └── ...
```

重启 Codex 或刷新 Skills 后，输入：

```text
$fuxa-industrial-iot-skill
```

然后可以直接说：

```text
根据 variables.json 给船舶主机做一个 1920x1080 机舱监控大屏。
客户已经声明的变量类型不要重新猜；未声明的再根据参数编码、名字和单位判断。
先只生成预览和绑定计划，不要修改 FUXA。
```

## Codex 用户级安装

复制到：

```text
~/.agents/skills/fuxa-industrial-iot-skill/
```

Windows 通常对应你的用户目录下：

```text
C:\Users\<用户名>\.agents\skills\fuxa-industrial-iot-skill\
```

## 只运行脚本

不安装 Skill 也可以：

```bash
cd fuxa-industrial-iot-skill
npm test
```

Node.js 需要 18+，无需安装第三方 npm 包。

## 连接 FUXA

推荐把 API Key 放到环境变量：

PowerShell：

```powershell
$env:FUXA_API_KEY="你的key"
node scripts/probe-fuxa.mjs --url "http://你的FUXA:1881" --api-key-env FUXA_API_KEY --out probe.json
```

不要把真实密码/API Key 写入模板 JSON 或提交 Git。

## 多机器检查

```powershell
node scripts/check-fuxa-fleet.mjs --config templates/fuxa-instances.example.json --out fleet.json
```

每个实例可以引用不同的环境变量，因此测试/生产凭证不会写到同一个配置文件里。

## 接工业云 API

先复制：

```text
templates/industrial-cloud.config.example.json
```

改成你的真实接口，先 dry-run：

```powershell
node scripts/industrial-cloud-bridge.mjs --config industrial-cloud.config.json --once --dry-run
```

确认映射正确后才去掉 `--dry-run`。

## FUXA 项目修改

任何项目 patch 默认只打印，不执行：

```powershell
node scripts/apply-to-fuxa.mjs --url "http://你的FUXA:1881" --api-key-env FUXA_API_KEY --patch patch.json
```

确认后才允许：

```powershell
node scripts/apply-to-fuxa.mjs --url "http://你的FUXA:1881" --api-key-env FUXA_API_KEY --patch patch.json --apply --backup-dir .\backups
```
