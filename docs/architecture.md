# 架构说明

## 1. 定位

### 1.1 职责边界

FUXA 是可视化层，不是数据源，也不是系统记录。设备数据保留在上游云平台，FUXA 负责把已经采集到的数据渲染成可读的画面。

```text
  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
  │  现场设备 │───▶│  边缘网关 │───▶│  云平台   │───▶│   FUXA   │
  └──────────┘    └──────────┘    └──────────┘    └──────────┘
    Modbus/OPC      采集与转发      API / 时序库     组态与画面
```

| 层 | 职责 |
|---|---|
| 现场设备 | 产生工艺数据 |
| 边缘网关 | 采集、协议转换、断点续传 |
| 云平台 | 设备模型、数据存储、对外开放 API |
| FUXA | 画面、仪表、趋势、报警呈现 |

### 1.2 边界约束

- 不绕过云平台 API 直接查询平台数据库。
- 不对同一台设备建立第二条写入链路。若网关已持有设备连接，FUXA 应向网关或平台取值，而不是再开一条并行通道。
- 客户门户仍是面向产品的入口，FUXA 可嵌入其后台，也可独立部署。

## 2. 数据接入方式

| 方式 | 形态 | 适用场景 |
|---|---|---|
| WebAPI 拉取 | FUXA 直接读取云平台 REST 接口 | 接口稳定、鉴权简单、JSON 结构固定 |
| 只读桥接 | 独立进程轮询平台接口，写入预建的 FUXA 标签 | 平台接口只读、结构易变或需要整形 |

推荐只读桥接：它把 FUXA 与上游接口解耦，并保持平台作为唯一写入方。

## 3. 变量语义

判定优先级从高到低：客户显式声明、平台物模型元数据、运维维护的编码映射、名称与单位启发式、安全兜底。置信度低于 0.70 的变量标记为待确认，不驱动报警与控制。

写权限只来自显式声明，不从名称或数据类型推断。详见 [`references/variable-semantics.md`](../references/variable-semantics.md)。

## 4. 渲染契约

画面元素全部使用 FUXA 原生控件，由 FUXA 在运行时更新。每个带变量的图表元素至少产出一个绑定标签的原生控件；校验器会拒绝只有图形没有绑定的元素。

控件类型、挂载容器与配置项详见 [`references/widget-catalog.md`](../references/widget-catalog.md)。

## 5. 版本兼容

先探测目标实例的能力，再决定用什么控件，不按版本号硬编码分支。参考锚点与探测接口见 [`references/fuxa-compatibility.md`](../references/fuxa-compatibility.md)。
